## 背景

项目需要一条可重复执行的语料预处理流程，把原始中文文档转换为可用于检索的分块数据。当前 `plan/corpus/documentProcess.txt` 已经描述了处理流程、存储位置和分块规则，但这些要求还没有沉淀为可执行的 OpenSpec 变更契约。

## 变更内容

- 新增语料处理能力，从 `data/raw` 加载源文档。
- 支持 PDF、TXT、DOCX 等常见文档格式。
- 新增文本规范化和自然段恢复：处理 TXT 或导出文本中的硬换行，避免把一行误当成一个自然段。
- 新增初步语义分块：按恢复后的自然段拆分文档，比较相邻自然段语义，相近则合并为同一块。
- 当连续多段语义相近时，设置最大连续段数并强制截断，避免单个分块过长。
- 新增二次动态分块：根据内容类型继续细分初步分块。
- 为每个最终分块添加元数据，包括唯一 id、内容类型、来源文档和顺序信息。
- 将处理后的语料结果保存到 `data/corpus`，并使用 SQL 数据库做长期存储。
- 使用 `model/corpus` 下的已有模型完成语义相似度判断。

## 能力

### 新增能力
- `corpus/documentProcess`: 覆盖原始文档加载、初步语义分块、二次动态分块、分块元数据和语料结果持久化。

### 修改能力
- 无。

## 影响

- 新增或更新与 `plan/corpus/documentProcess.txt` 对应的语料处理代码。
- 从 `data/raw` 读取源文档。
- 将处理后的分块数据写入 `data/corpus` 下的 SQL 数据库。
- 使用 `model/corpus` 下的语义分块模型。
- 可能需要加入 PDF 和 DOCX 文档解析依赖。
