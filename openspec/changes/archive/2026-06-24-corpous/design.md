## 背景

`plan/corpus/documentProcess.txt` 定义了当前中文文档预处理需求。`plan/` 目录是需求来源，并且目录结构需要映射到实现文件，因此本变更应把该计划实现为对应的 Python 模块 `corpus/documentProcess.py`。

整体流程从 `data/raw` 中的原始文档开始，解析支持的文档类型，先进行文本规范化和自然段恢复，再执行两轮分块，添加元数据，并把处理后的语料记录保存到 `data/corpus` 下的 SQL 数据库。初步语义分块依赖 `model/corpus` 中已有的语义模型，并需要在连续多段语义相近时通过最大连续段数强制截断。

## 目标 / 非目标

**目标：**
- 按 `plan/corpus/documentProcess.txt` 实现语料文档处理模块。
- 保持实现文件布局与 `plan/` 目录布局一致。
- 产出带有稳定元数据字段的确定性分块记录。
- 避免把 TXT 中的硬换行、导出换行或显示宽度换行误判为自然段边界。
- 让文档加载、初步语义分块、二次动态分块、元数据补充和持久化步骤都可以独立测试。

**非目标：**
- 不构建完整的检索或向量搜索流水线。
- 不训练新的语义分块模型。
- 不添加文档上传或语料审核界面。
- 不构建复杂数据库迁移系统，只实现当前语料处理所需的本地 SQL 存储。

## 设计决策

1. 实现路径镜像 `plan/` 路径。
   - 决策：将 `plan/corpus/documentProcess.txt` 实现为 `corpus/documentProcess.py`。
   - 原因：用户已明确 `plan/` 是当前工程要求来源，并且每个 `.txt` 对应一个同结构 `.py` 文件。
   - 备选方案：使用更 Python 风格的 `corpus/document_process.py`；未采用，因为会破坏计划到代码的结构映射。

2. 将流水线拆成清晰函数。
   - 决策：分别提供文档加载、文本规范化、自然段恢复、初步语义分块、二次动态分块、元数据补充、分块保存等函数。
   - 原因：计划文件本身按这些步骤描述，拆分函数后更容易测试和替换。
   - 备选方案：只提供一个端到端处理函数；未采用，因为模型调用、内容分类和保存逻辑会难以单独验证。

3. 初步语义分块必须基于自然段而不是物理行。
   - 决策：TXT 和抽取文本先按空行、标题、缩进代码块、表格形态等信号恢复自然段；普通硬换行应合并到同一自然段。
   - 原因：许多 TXT 文档会按显示宽度换行，如果直接按行切段，会得到大量不完整句子，语义相似度判断也会失真。
   - 备选方案：直接按每个非空行作为段落；未采用，因为源文档中已经存在一行一段的假段落问题。

4. 根据内容类型选择分块大小。
   - 决策：二次动态分块先识别内容为代码、表格或普通文本，再应用对应的分块大小和重叠长度。
   - 原因：计划文件对不同内容类型给出了不同分块规则。
   - 备选方案：所有文本使用同一分块大小；未采用，因为会忽略代码和表格结构，降低后续检索质量。

5. 用适配层接入语义比较模型。
   - 决策：初步语义分块通过从 `model/corpus` 加载的模型适配器计算语义相似度，而不是直接绑定某一个模型库。
   - 原因：计划要求使用已有模型，但仓库中尚未固定具体模型运行时。
   - 备选方案：硬编码某个 embedding 或相似度库；未采用，因为首版实现会过于脆弱。

6. 语义相似度阈值采用默认值加校准流程。
   - 决策：首版默认阈值为 0.72，并提供相邻自然段相似度分布报告，用于人工抽查后调整配置。
   - 原因：不同模型和语料的相似度分布不同，固定阈值容易过合并或过拆分。
   - 备选方案：只使用固定阈值；未采用，因为用户当前无法预先判断合适阈值。

7. 用本地 SQLite 作为首版 SQL 存储。
   - 决策：将分块和元数据保存到 `data/corpus/corpus.db`。
   - 原因：计划要求借助 SQL 数据库做长期存储，SQLite 不需要额外服务，适合当前本地语料处理流程。
   - 备选方案：接入 MySQL 或 PostgreSQL；未采用，因为当前仓库没有服务配置，首版会引入不必要的部署复杂度。

## 风险 / 取舍

- 不支持或损坏的文档 -> 对单个文件返回结构化加载错误，并继续处理其他有效文件。
- 硬换行导致伪段落 -> 在语义分块前做自然段恢复，并为硬换行合并、空行分段、代码块保留分别加测试。
- 相似度阈值不合适 -> 输出校准报告和抽样结果，先人工检查后再调整配置。
- 语义模型不可用 -> 在分块前暴露清晰的配置或运行时错误，不静默退化为普通分块。
- 分块边界切断重要上下文 -> 使用计划中定义的重叠长度，并保留来源元数据，便于追溯和调整。
- 连续语义合并导致分块过长 -> 通过最大连续段数强制截断初步分块。
- SQLite 文件损坏或写入失败 -> 保存前创建目录，写入失败时返回明确错误并避免吞掉异常。
